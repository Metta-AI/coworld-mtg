#### 3a. Concrete storage and API

Add `#[serde(skip, default)] pub(crate) departure_suppression_scope: DepartureSuppressionScopeState` to `GameState` in `types/game_state.rs`. Define small `pub(crate)` structs there (no engine enum additions):

- `DepartureScopeId(u64)` identifies an owner within one synchronous call tree. The monotonically allocated value is internal and reset only after both stacks are empty. It is not a rules-object id and never enters an event or save.
- `DepartureSubject { object_id: ObjectId, incarnation: u64 }` binds a selected live incarnation before a move. Reuse the object's existing `incarnation`; no new ZoneChangeRecord incarnation field is needed.
- `DepartureEventKey { event_offset: usize, object_id: ObjectId, turn_zone_change_index: usize }` identifies the actual emitted ZoneChanged occurrence. The event's `from == Some(Battlefield)` is also checked at consumption. Offsets always refer to the same append-only `events` vector borrowed by the owner helper; no raw pointers/vector addresses.
- `DepartureScopeFrame { id, event_start, candidates, capture, emitted }`: candidates are deduplicated `DepartureSubject`s; `capture: Option<DepartureSuppressionCapture>` stores evaluated before outcomes keyed by those subjects; emitted stores claimed event keys. `DepartureSuppressionCapture` holds outcomes, not a GameState, functions, borrowed filters, or a saved layer world. `Some` includes candidates with empty outcome vectors. `None` means this frame owns no fresh before/after layer boundary (zero battlefield candidates, or the explicitly limited independent nested case below); it is not evidence of no suppressors.
- `DepartureSuppressionScopeState { next_id, frames, member_bindings }`, with `member_bindings: Vec<Option<DepartureMemberBinding>>`; `DepartureMemberBinding { owner: DepartureScopeId, subject: DepartureSubject }`. `Some` is one explicit borrowed member; `None` is a lexical barrier that prevents an independent inner action from borrowing an ancestor's member. The top entry alone controls leaf borrowing; never search through a barrier for a matching ancestor object.

Use ordinary owned containers and short borrow scopes. `Default` is empty; derive Debug/Clone for the state-side data as required by `GameState`. The opaque `DepartureScopeToken` is defined in `zones.rs`, minted only by the owner wrapper, and lends its id to closures by reference; do not implement Clone/Copy/serde/default on the token. It cannot be retained in GameState, a pending carrier, or a returned result. No `unsafe`, thread-local storage, RefCell, global layer lock, or new dependency is needed.

The owner wrapper pushes an owner frame and a member barrier, calls `body`, saves its returned `R`, finalizes/pops exactly its own frame and restores the member stack to its entry depth, then returns `R` unchanged. `R` may be the existing Result, move-result enum, or loop-control result; no new result variant is required. A `return` or `?` inside the closure returns to this epilogue. Private begin/finish workers may implement the internals, but production callers cannot obtain a bare begin token and forget to finish it. `with_departure_member` validates the still-live selected incarnation against that owner's candidates, pushes one binding, invokes the existing guard/replacement/move authority, and restores the prior binding on return. A no-longer-matching object cannot borrow the old incarnation's outcome. Sub-checks serving the same action receive the owner's borrowed token; they do not call the owner wrapper again.

`without_departure_member` is the same push/call/pop pattern with a `None` binding and no capture/flush. #### 3b. Leaf and layer algorithm

1. At owner entry, determine live battlefield candidates and their incarnations before the first mutation. With at least one such candidate and **no already capturing ancestor**, call existing `layers::flush_layers` once, then evaluate before outcomes for every candidate with the shared functioning-static/filter authorities. Push `capture = Some(...)` even when every outcome is empty. With no battlefield candidates, push an empty frame without flushing: a mass entry must not capture unrelated Devour victims as departure members.
2. Wrap each producer's existing per-object operation in `with_departure_member`. Leave victim selection, target validation, replacement choice, destruction guards, and sacrifice controller checks at their present authorities. In SBA, thread the one iteration token to its departure sub-checks and wrap their per-object movement operations; a subset's previous stamp cannot open or finish a scope. For other producers, place the member wrapper around `destroy_single_object`, the proposed-destroy replacement/delivery call, `sacrifice_permanent`, `process_one_zone_move`, or `move_object`, as appropriate.
3. `move_to_zone` and `move_to_library_at_index` keep their public signatures. Factor each existing mutating body into a private inner function or equivalently wrap its body so all returns pass the leaf epilogue. A potential actual battlefield departure with a valid top member binding uses that owner's before outcome and registers its actual emitted key there; **no before or after leaf flush, no provisional Some(snapshot)**. Temporarily mask/consume the binding while inside the leaf's mutating body so recursive leaf work cannot claim it again. Preserve the original key separately for that leaf's own ZoneChanged emission. Capture the pre-move incarnation before it bumps; record the event key at emission, after assigning `turn_zone_change_index`. Do not rediscover membership by scanning every event with the same object id.
4. An unowned battlefield leaf with no capturing ancestor uses a one-object `with_departure_suppression` and member call around its original body. This is the standalone path: flush/evaluate before the mutation; after its own actual departure finishes, flush/evaluate the immediate after world before returning. A continuous-effect source that leaves and thereby enables/disables a surviving suppressor must be reflected in that after outcome even when the before suppressor list was empty. Non-battlefield leaves and genuine no-op/rejected moves create no departure record or snapshot. Known no-op guards may run before opening the frame; all behavior of existing guards remains intact.
5. At a capturing owner's finish, there are no live member bindings belonging to that owner. Resolve its claimed keys only within `event_start..events.len()` and check event kind, Battlefield origin, object id, and per-turn index. Flush once for the post-action world if it emitted any actual battlefield departures; evaluate after results against each recorded departure subject using the existing record filter authority and pre-death characteristic rule. #### 3c. Nested ownership, independent causes, and the exact limit

**One action with nested delivery:** an outer SBA iteration is the owner; its zero-toughness/lethal/etc. sub-checks borrow the token and their leaves claim events for that same owner. A Destroy owner borrows into destruction → replacement → pipeline → leaf. None of those transparent calls recaptures or closes; ordinary nested function depth is not a new event. The token and bound incarnation, rather than candidate overlap alone, distinguish ownership. If a helper needs to serve both a root action and an existing action, provide a private token-taking implementation and keep the root wrapper at the actual producer; do not infer sharing from nonempty global state.

**Independent action with no capturing ancestor:** it owns its own frame and both flush boundaries, even if a non-departure parent (for example, a graveyard-to-battlefield ChangeZone group) is active. That parent's empty battlefield candidate set does not own the child's sacrifices. When a Devour choice pauses, all lexical scopes end before the prompt is returned; its choice handler subsequently opens its own victim scope. The existing `devour_eligible_snapshot` remains the sole eligibility authority and is unchanged.

**Independent action inside an already capturing departure action:** the new barrier prevents sharing and the ancestor check prevents adding a flush halfway through the outer group. A nested owner has `capture = None`; a nested unowned leaf keeps `trigger_suppression = None` and the existing missing-history compatibility path. It may retain its existing own co-departure stamping, but cannot contribute events to the parent's owned set. Do not manufacture an authoritative empty snapshot or evaluate stale effective abilities and label the result a captured child world. The parent retains its captured outcomes for its directly owned members and finalizes only those keys. General rules-correct before/after worlds for such a reentrant child are a **pre-existing layer-world limitation**, not newly supported by this patch. It does not authorize altering the child's effects, cause events, matching-origin policy, or existing flushes. Active tests must prove ownership isolation and no added mid-group flush; an ignored desired-timing characterization records the remaining gap where a reached fixture needs a separate child layer world.
