## Detailed decisions at the disputed seams

The battle classification is supportable at its actual first production boundary. In the inspected shipped formats, an alive Siege controller with no alive legal opponent has reached the game's terminal condition before normal public SBA iteration can exercise the zero-choice movement. Changing only one elimination field, constructing an unsupported topology, changing team flags to route unrelated semantics, or bypassing the public terminal check would not prove public reachability. V10 does not permit those shortcuts. Its lower-level mutation has a concrete limited claim: the retained physical member handoff gives an actual private-arm departure an authoritative singleton snapshot; removing that member handoff yields None beneath an active owner. The public terminal and protector-choice controls establish why that lower-level claim is the appropriate classification. This is not an exemption for the other eight publicly reachable SBA arms.

The batched adapter fixture is specifically capable of reaching the inner adapter. The surviving noncreature observer and Hushbringer see one creature and one noncreature depart in a single selected DestroyAll group. The noncreature supplies an eligible outer seed even while the creature is suppressed. The event and top-level batched filters are both supplied. Correct inner filtering gives one counted member and the fixed-plus-count payoff of 11; replacing only the inner adapter with the raw matcher admits the creature and predicts 12. Creature-only, noncreature-only, no-Hush, both-order, peer, and actual snapshot controls prevent a vacuous pass. This assessment follows the source path through outer trigger collection, `matching_batched_zone_change_records`, and counted event context; runtime evidence is still required.

The second batched fixture targets the separate inner whole-death gate. A destination-functioning self-arrival Any/SelfRef ability remains eligible with Hushbringer alive, while an Equals(Battlefield) death sibling is suppressed. The correct Any batch yields the real payoff of 2. Restoring the old whole-death gate only inside the batch collector predicts an empty batch despite an eligible outer Any seed. Both orders and no-Hush controls make the old gate distinguishable without changing the supported-source classification. These two exact mutations cannot be replaced by another outer-adapter failure or by a single-subject masked fixture.

The performance disposition matches the implementation seam. `TriggerSuppressionSnapshot` Some branches avoid legacy scans, while the None helper discovers active suppression statics on each invocation. The plan neither promises a new fallback cache nor uses an unavailable Scute snapshot to claim a measured speedup. The required final report must retain that cost boundary and the unavailable historical benchmark, even if every behavioral Scute guard passes.

Canonical executable reuse is a provenance option, not a reduced restoration test. The original fresh compilation must bind the complete source, test overlay, generated/build inputs, toolchain/configuration, and executable. Restoration must compare all canonical source bytes and runtime inputs, then run the same exact tests/controls again. During this review, root reported a supplemental direct canonical run that omitted Cargo's effective `RUST_MIN_STACK` and stack-overflowed before any mutant ran. This is a reported setup failure, not independently certified semantic evidence. V10's existing relevant-environment/working-directory/runtime-input requirement already rejects counting that run. Reconstruction of the effective nonsecret Cargo environment, loader paths, and package cwd must precede a passing canonical run; the earlier failure must remain in the record. If identity cannot be established, the specified fresh restoration compilation is required. No waiver is granted here.
